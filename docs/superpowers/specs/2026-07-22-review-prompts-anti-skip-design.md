# 2026-07-22 审查提示词防漏设计

## 背景

`D:\AI\提示词精选\godot-mcp-enhanced\` 下有 5 份审查提示词:`通用版.md` + `专项1-安全RCE.md` + `专项2-可靠性.md` + `专项3-GDScript编辑器.md` + `专项4-测试缺口.md`。每份的「交付落地」段都要求产出一份独立的 Obsidian 报告。

2026-07-22 用这 5 份跑审查,本应产出 5 份报告,实际 Obsidian 只有 4 份——**「专项2-可靠性」未生成独立报告**,其主题(进程通信+崩溃恢复+并发)的发现被通用版产出的「三层架构综合审查（RCE面+进程通信+协议正确性）」吸收。

### 根因(用户确认 4 条全中)

1. **通用版覆盖误判**:通用版【P0 进程通信可靠性】+【P1 并发】与专项2 高度重叠,跑完通用版后误判专项2 可省。
2. **缺总清单索引**:没有任何地方列出「5 份提示词 ↔ 5 份期望报告」对应表,跑完没核对,漏一份不自知。
3. **定位界限模糊**:提示词未讲清「通用版=概览基线 / 专项=单维度深挖 / 二者不可互替」,审查者分不清差异。
4. **工作流易遗漏**:跑 5 份(并行多会话 / 顺序跑)的方式本身容易漏,与提示词内容无关。

## 目标

更新 5 份审查提示词,使下次跑能稳定产出 **5 份独立报告**,不漏。对症上述 4 根因。

**约束**:提示词正文内容(深挖清单 / 已知非 bug / 基线实测命令 / 横切铁律 / 输出格式 / 交付落地)一律不动,只在顶部加防漏结构 + 新增一份索引。采用 brainstorming 选定的**方案 1(加索引 + 定位块)**,不重写通用版(排除方案 2),不做通用版瘦身(排除方案 3)。

### B. 5 份提示词顶部各加统一块

插在每份现有的「维护基线日期:**2026-07-22**」段之后、`---` 分隔线或提示词正文之前。统一文案(方括号部分按份替换):


各份【本份定位】+ 期望报告名具体化(取自 A.1 对应表)。

**B 块只含定位 / 不可互替 / 指向索引三要素;各份正文已有的「交付落地」段是详细流程(报告写哪、待办同步、frontmatter / callouts),保留不合并、不删除。**

### C. `专项2-可靠性.md` 额外加「与通用版边界」导读(对症根因 1)

专项2 是漏跑重灾区,单独加强。

**定位:C 块是专项2 自身深挖清单(`专项2-可靠性.md:28-46` 第 1-8 条)的导读,不是额外新增项**——目的是让审查者一眼看出"本专项深挖什么、与通用版有何不同",防止跑完通用版误判可省。

通用版【P0 进程通信可靠性】+【P1 并发】+【P1 历史 bug 模式】已**横切提及** scheduleReconnect 状态机、重连耗尽 maxReconnectAttempts、health-monitor、资源泄漏、降级/fallback 对称性(通用版 grep 实测均命中)。本专项做两件事:

1. 对上述横切项**单维度系统深挖**(通用版是横切一句,本专项是深挖清单 + 调用链 + 行号);
2. 覆盖通用版**完全未单列的边界场景**(grep 实测 0 命中):

- TCP 半开(OS 崩溃无 FIN,WS `'close'` 永不触发 → 心跳连续失败检测)
- in-flight 工具调用归宿(重连中:超时 / 错误返回 / 永久卡死——通用版反向清单仅提 do_not_retry 一面)
- 超时链放大(工具级超时 × 自动重试 → 雪崩;退避策略)
- 进程生命周期(zombie / orphan WS / 端口占用恢复)
- 崩溃优雅恢复 + 资源释放(编辑器 kill -9 / Godot 崩溃;通用版仅在测试缺口段提一句)

收尾:"跑完通用版 ≠ 跑完本专项——通用版横切提及,本专项系统深挖 + 覆盖通用版未单列的边界场景,二者不可互替。"

## 范围外(YAGNI)

- 不重写通用版深挖清单(方案 2,改动过大,失去「全维度基线」原意)。
- 不改各专项的深挖内容 / 已知非 bug / 基线实测命令(本轮纯加防漏结构)。
- 不给 `D:\AI\提示词精选\` 目录建 git 仓库——故 B/C 块改动不可 git 回滚,以实施前置 `.bak\` 备份兜底;是否纳管版本另议。
