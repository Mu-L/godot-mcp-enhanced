- 自 v0.19.1（2026-06-27）后，本地领先 origin 211 commit，其中包含新增 cpp 模块 `scaffold_gdextension`（commit `d08918a`，已纳入 capability-matrix）。cpp 是新工具赛道卖点，应作为 minor bump 的主打内容，版本号升到 0.20.0。
- 现有 `D:\GitHub\godot-mcp-enhanced\test\e2e-full-tool-verification.test.ts` 已有 ~45 个 case，但用极简 fixture（`test\fixtures\e2e-project\`，仅 `main.tscn` + `main.gd`），导致：
  - animation / particles / tilemap / nav / material / signal / audio 等在空场景下大多返回 not-found / error，是"调用不崩"级别的浅验证，未验证正路径；
  - bridge(game) / editor 只测 error-path（无运行态正路径）；
  - android 完全未覆盖。
- **矩阵现状强化动机**（`D:\GitHub\godot-mcp-enhanced\docs\capability-matrix.md:9`）：当前 **L2 覆盖：covered 0 / partial 0 / none 30** —— 30 个工具 L2 全空，正是本 spec 要解决的核心问题。

## 目标

1. **28 个顶层工具三层全覆盖**（L1 headless 静态 / L2 运行态 / L3 特殊环境），全自动化（vitest）、可复跑。**显式排除 2 个**：`manage_tools`（测试基础设施自身的元工具，启停工具组，不宜在受测套件里自指）、`load_skill`（本地知识库 SKILL.md 检索，无 Godot 依赖、无场景副作用）。

3. 版本号 0.19.1 → 0.20.0，5 个版本元数据文件一致（`npm run version-check` 通过）。

## 非目标（YAGNI）

- **不做完整可玩 demo**：工作量大、验证范围会被 demo 内容牵着走（demo 没有的子系统仍要另造场景）。靶子保持**最小化**，只放各工具正路径验证所需的真实对象。
- **靶子不加 autoload**：理由是 YAGNI + 三层共用靶子降复杂度（autoload 非正路径验证所必需）。**注意**：autoload 本身不导致死锁（旧论据"#89399 死锁"已被 memory `godot-test-project-status` 2026-06-23 更新推翻——#89399 是特定 RPG 项目环境 + headless 假阳性，干净项目 autoload 正常）；如未来要验证 autoload 相关行为，可另加，不受本设计劝退。
- **不重写现有 e2e-full-tool-verification**：扩建（切换 fixture + 新增 case），不推倒重来。
- **不强制 android deploy**：无连接设备时 `deploy` skip；`list_devices` 返回空也算正路径。
- **不做 CI Godot 配置**：本机 GODOT_PATH 跑全套；CI 无 Godot 时显式 skip + stderr 告警（沿用 IMPORTANT-9b 反假绿模式，实据见 `D:\GitHub\godot-mcp-enhanced\.claude\reviews\2026-06-18-godot-mcp-enhanced-test-quality-review.md:181` + 代码注释 `test\e2e-full-tool-verification.test.ts:24`），不静默假绿。

### L2 — 运行态层（vitest + 真启 Godot 进程）

- **bridge(game)**：`game_bridge_install` → `run_project` 启 `real-project` → `ping` → `get_tree` → `find_nodes` → `set_node_property` → `wait_for_property` → `take_screenshot` → `monitor_start/poll/stop` → `watch_start/poll/stop` → `find_ui_elements` → `click_button` → `stop_project`。afterEach：kill 进程 + 清密钥文件（避免跨用例密钥/TTL 残留污染；并规避密钥权限收紧循环——见 `D:\GitHub\godot-mcp-enhanced\.claude\rules\godot-mcp-bridge.md`「密钥权限循环」条目：Bridge 首次运行后 icacls 收紧只读 → 重写失败 → `GODOT_MCP_BRIDGE_PERSISTENT_SECRET=true` 治本）。
- **runtime(recording)**：依赖 bridge 真链路 → `recording_start` → `send_key`/`send_mouse_click` → `recording_stop` → `recording_play`。
- **profiler**：启游戏 → `snapshot` → `start` → `get_data` → `stop`。
- **editor**：`launch_editor` 启 **GUI 编辑器** → `editor_sync_start` → `editor_get_scene_tree` → `add_node` → `remove_node`（验证 undo）→ 停止。**代价**：GUI 重、本机慢、CI 无显示不可行 → 守卫 `describe.skipIf(!hasGodot || !process.env.E2E_EDITOR)`（合取：editor 启用隐含 Godot 必须存在），skip 时同样 stderr 告警（对齐 IMPORTANT-9b 反假绿一致性）。

### L3 — 特殊环境层

- **multi_instance**：设 `GODOT_MCP_MULTI_INSTANCE=true` 编排 2 个 Godot 实例 → `godot_list_instances` → `godot_select_instance`。
- **dynamic**：`godot_list_dynamic_routes`（现有是静态版，升级为真连接 Godot 后探测）+ `godot_advanced_tool`（代理 test/verify_delivery 等）。
- **android**：adb 已就绪（`D:\Android\Sdk\platform-tools` 在 PATH）→ `list_devices` / `get_preset_info` / `check_template` / `logcat` 真验证。**无连接设备时 `list_devices` 返回空（正路径），`deploy` 需设备则 skip**。

### 反假绿

- 本机 `GODOT_PATH` 已配 4.6.2，全套真跑。
- 所有依赖真实 Godot 的测试用 `describe.skipIf(!hasGodot)` 守卫 + `process.stderr.write` 显式告警（vitest 吞 `console.*`，必须 stderr）。
- CI 无 Godot 时这些测试**显式跳过**并在日志可见，不静默假绿。

| 维度 | `test\regression\*` | 本 spec 扩建的 `e2e-full-tool-verification` |

## 节 4 — 环境前提与权衡决策

**已探明前提**：

| 前提 | 状态 |
|------|------|
| Godot 4.6.2 + GODOT_PATH | ✅ `D:\godot\Godot_v4.6.2-stable_win64.exe` |

**权衡决策（采用推荐默认，终审时可调）**：

1. **editor GUI 测试**：默认 skip，`E2E_EDITOR=1` 显式启用，且 `skipIf(!hasGodot || !process.env.E2E_EDITOR)` 合取 + stderr 告警。理由：避免日常 `npm test` 被 GUI 编辑器拖慢，CI 无显示本就跑不了。
2. **android deploy**：无连接设备时 skip，`list_devices` 返回空算正路径。理由：deploy 是副作用操作（推 APK 到设备），无设备时无法验证，不应阻塞测试。
3. **CHANGELOG 0.20.0 主打**：cpp `scaffold_gdextension` + 全工具验证靶子。理由：cpp 是 0.19→0.20 的功能性增量主体，验证靶子是质量基础设施增量。

## 风险与对策

| 风险 | 对策 |
|------|------|
| headless 运行态测试残留 Godot 进程 | afterEach kill 进程 + `ps.resetState()`（沿用现有 e2e 模式） |

| adb 无连接设备 | deploy skip；list_devices 空列表正路径 |
| 现有 e2e case 切 fixture 后行为变化 | 逐 case 核对，浅验证升级为正路径断言时更新预期值 |
