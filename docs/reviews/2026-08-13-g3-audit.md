## 初审判定:BLOCKING ISSUES

审查抓到一个**纯单元测试漏掉的结构性缺陷**(置信度 88):

### B-1. confirm_and_execute 绕过审计 + 令牌请求留虚假 ok=true
**根因链**:
1. `requiresConfirmation`(guard.ts:64-68)对所有非 read 操作返 true
2. write/destructive 工具直接调用 → 返回令牌响应(普通 ToolResult,非 InputRequiredResult)→ audit after-hook 照跑,**记虚假 ok=true**(操作未执行)
3. confirm_and_execute 真实执行(`_confirmExecute→dispatchTool` :742-784)**绕过 executeMiddleware** → 真实结果**从不记审计**

净效果:最该审计的(write 真实执行)漏记 + 记虚假成功 → `suggest_rollback` 给"删未创建文件"建议 = 误导。

### I-1. suggest_rollback entry_index 错位
readAuditLog entries[] 无 index 字段 + limit/since 视图 vs 全量下标错位。

## 修复措施(全部落地)

### B-1 修复(3 处)
1. **audit middleware 检测令牌响应跳过**(`ToolDispatcher.ts` buildMiddleware):`isTokenRequestResult(result)`(content 含 `"requires_confirmation":true`)→ return,不记虚假成功。逻辑抽到 `audit-log.ts`(可单测)。
2. **`_auditConfirmedExecution` 补真实审计**(`ToolDispatcher.ts`):confirm_and_execute 两处执行点(:361 opt-in/:398 第二轮)调 `_auditConfirmedExecution(pending, startTime, result, traceId)`,用 pending 的真实 tool/action/risk + 真实执行结果 + `details.confirmed:true` 标记补一条审计。
3. **全 body try/catch 防御**:`_auditConfirmedExecution` 整个 body 包 try/catch —— 审计是 best-effort side effect,任何失败(含 mock 环境 / 路径不可写)都不影响工具结果(对齐 G2 catch 哲学)。

### I-1 修复
- `readAuditLog` entries[] 每条附全局 `index`(AuditEntry & {index})[]
- `audit.ts` suggest_rollback 用 `find(e => e.index === idx)` 精确定位(不再下标错位)

### 测试加固
- `isTokenRequestResult` 4 单测(令牌响应→true / 普通成功→false / 错误→false / 空→false)
- 完整 ToolDispatcher audit 集成测试(write 触发/confirm 真实审计/read 跳过)**defer** —— mock 基础设施复杂(getActionRisk/requiresConfirmation/_confirmExecute 都要 mock),B-1 代码层修复 + isTokenRequestResult 单测 + _auditConfirmedExecution 全 try/catch 防疫已覆盖核心;残留风险:confirm 真实审计的端到端锚定无自动化测试。

## 工程教训(已进 memory)

1. **审计中间件与确认门控共用风险信号源的致命耦合**:requiresConfirmation 与 audit 触发都读 getActionRisk,而确认门控把执行 divert 到绕过 middleware 的路径(_confirmExecute→dispatchTool),"审计非 read" 退化为"只审计令牌请求(虚假成功),漏审计真正执行"。设计事后审计必须独立确认:被审计调用是否真执行了(检测 requires_confirmation 响应 / 确认执行路径补审计点)。锚点 guard.ts:64-68 + ToolDispatcher.ts:405-420,742-784 + middleware.ts:61-63。
2. **纯单元测试无法发现 middleware 接线级语义缺陷**:audit-log.ts 17 单测全绿却漏 B-1(缺陷在 middleware↔确认门控↔dispatcher 集成交互层)。涉及跨子系统控制流的新功能,集成测试锚点是必选项。
3. **审计 best-effort 必须全 try/catch**:_auditConfirmedExecution 的 try 只包 appendAuditLine 时,try 外的 getActionRisk/resolveProjectPath 在 mock 环境抛 → 主 catch 兜底成 Internal error,污染工具结果。审计 side effect 的全部逻辑必须包在一个 try/catch,永不影响工具。
