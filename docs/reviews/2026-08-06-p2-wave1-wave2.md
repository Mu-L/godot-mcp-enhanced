### ⚠️ I-2 — P2-4 playtest.step frames=1 时无实际推进(置信度 85)

**修复**:加 `_added_this_frame: true` 标记,加入帧不递减(`entry["_added_this_frame"] = false; continue`),下一帧才开始计帧。修正误导注释("coroutine"→"计数器轮询")。

## 值得进 memory 的工程教训

1. **"多副本常量必须引用同一源"是 plan 警告但易踩的坑**:P2-4 plan(:150/:194)明文要求"不新抄",实现仍新抄且抄旧版(漏 instance)。教训:plan 的安全命脉声明不能依赖实现者自律,必须有 defects.ts 检测兜底;新副本出现时 detect 须同步扩到新文件。
2. **"字面量契约测试会假绿"二犯**:game-bridge-playtest.test.ts 全是 TS 静态 enum 断言,GD 侧零测试 → B-1 漂移静默通过。与 P1-4 cacheHints era-gated 假绿同构。教训:跨 TS-GD 契约,光测 TS 侧不够,须 GD 侧行为测试或跨语言一致性 detect。
3. **check:gdscript 范围盲区**:原只编译 addons/,漏 src/scripts/(mcp_bridge.gd 是运行时主战场)。已扩编译范围。
4. **plan 决策 vs 实现偏差需审查者独立 grep 验证**:plan 说"step 走 coroutine",实现改成计数轮询,注释还残留"coroutine"。审查者不能信 plan/注释,必须 read 实际实现。
5. **ServerOptions 字段 inert 是隐蔽 dead code**:P2-1 overrides 字段被解析存入但 install 永不发生。这类"解析-存储-部分消费"链路单测难抓,建议 ServerOptions 字段加"消费点 grep 守护"或端到端集成测试。
