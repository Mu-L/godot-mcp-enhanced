## 审查发现与清偿

### B-1(Blocking,置信 88):_state_safe 放行几何类型,Vector2 序列化退化为字符串,容差对位置类完全失效

**发现**:`_is_safe_value` 对 Vector2/3/4 系返回 true → 裸 Vector2 经 JSON.stringify 退化为 `"(10.000001, 20)"` 字符串(仓库自证:`mcp_bridge.gd:2457` send_drag 注释"真机实证"且因此走 `_jsonify`)——TS 容差只对 number 生效,字符串退化让容差在 feature 核心场景(host/client 位置比对)完全失效,masteryee 坑原样复现。**测试盲区重合**:fixture 用常量 Vector2(两侧字符串相等不产生 diff),e2e 恰好通过但"微差 Vector2 容差判等"从未被验证。同根因衍生:INF 序列化 `1e99999`(TS 解析回 Infinity,`Math.abs(Inf-Inf)=NaN<=tol` 恒 false → 同值 INF 恒 diff)、NAN 序列化 `null`(值语义漂移)。

**清偿(三面)**:
- GD `_state_safe`:几何类型(Vector2/2i/3/3i/4/4i/Color)走既有 `_jsonify` 转 `{x,y,z}` dict(分量级数值走容差路径);float 加 `is_finite` 检查(INF/NaN 降级 str 防漂移)。
- TS `valuesEqual`:数值分支先 `va === vb` 严格短路(同值 ±Infinity 不经容差算术)+ NaN 显式判不等——同值 Infinity 正确判等。
- e2e 锚:fixture `toggle_p10_flag` 顺带微移 pos(+0.00001,容差内)——SYNC 用例现在真实验证"微差 Vector2 不误报 diff"(diffKeys 仍精确等于 ['flag','ticks'])。
- 单测 GD-b2(几何 dict 化断言)+ CMP-g(同值 Infinity 判等/不同值判 diff)。

## 工程教训(登 memory)

1. **"JSON 安全"≠"JSON 比对友好"**:_is_safe_value 防序列化失败,但几何类型放行后退化字符串,下游数值容差语义整体失效——数据出口管道要按"消费者拿什么类型比对"设计;同文件 _jsonify 先例就是答案,新代码没复用(审查者的 grep 命中:`mcp_bridge.gd:2457` vs `:1484`)。
2. **常量值测试会把序列化退化锁进绿色**:fixture 常量 Vector2 两侧字符串相等→测试过→以为容差在工作。"相等路径"的测试必须含受控微差才能验证比对语义本身。
3. **Godot JSON.stringify 三态非有限值**:INF→`1e99999`(TS 解析回 Infinity)/NAN→`null`——任何把 float 直接送进 bridge JSON 响应的新通道都要先过 is_finite。
4. **Git Bash heredoc 传中文给 python 的终端转码坑**:heredoc 内中文字符串经终端编码转换后与文件 utf-8 字节不一致,匹配/替换静默失真——涉及中文 pattern 的脚本一律 Write 工具落 .py 文件执行。
