## 值得进 memory 的工程教训

1. **MCP SDK 协议版本 opt-in 模式**:2026-era 版本只能通过 server/discover 被客户端选择,不污染 legacy initialize 握手 —— 追加现代版本到 supportedProtocolVersions 是安全 opt-in(legacy 零影响)

2. **capability-matrix 字段名是契约检查器的契约面**:check-contract.mjs 读取的字段名必须与 src/capability/ 生成器输出严格一致。未来改任一侧字段名须同步(CI 不校验字段名存在性,只校验值合规 —— 字段 rename 会静默致检查器"看不到"该字段)

3. **纯 JS pngjs 替代 sharp 的取舍**:sharp 是 native(node-libvips)跨平台安装痛点,pngjs 纯 JS 零 native 依赖,适合 MCP server 轻量图像处理 + 必须跨平台场景。代价:性能远逊 sharp,但低频够用
