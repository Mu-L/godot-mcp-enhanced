## 三、分级发现

### 架构债(应立项)

#### D1 · L2 e2e 白名单制治理失效中

**证据**:`.github/workflows/ci.yml:219-222` 注释自证——"P8 审查 N-1 (2026-09-12):补 p3-e2e/p8-e2e 进白名单——L2 列表是白名单制,新增 e2e 文件默认不进 CI……**p3/p8 连续两批漏加致热加载运行中改/删/回滚行为无 CI 护栏**"。白名单是 `ci.yml:222` 的一行硬编码文件列表。

**建议**:转 opt-out——L2 e2e 迁入约定目录(如 `test/e2e-l2/`)用 glob 收集,排除项显式列出;或新增 check 脚本对账"CI 文件列表 vs 测试文件内 `GODOT_MCP_E2E_L2` 标记"机械防漏。同类事故已连发两次,第三次的概率不低。

#### D2 · AGENTS.md 三层架构表述滞后于 dap 第四通道

**证据**:`src/tools/dap.ts:8-30` 头注释声明"TS 直连 editor 自带 DAP server(127.0.0.1:6006)";但 `src/core/editor-method-map.ts:109-121` 只登记 WS 通道的 debug 组,dap 不经此表。AGENTS.md「架构约束」的"editor 层工具需要登记 editor-method-map"表述不覆盖 dap。分发侧规则文档已更新(`src/tools/rule-templates.ts:90-98` 有 dap 专属段),仓库自用架构文档未同步。

**建议**:架构文档改为"层 = 目标进程域 × 通道矩阵"——editor 域两条通道(WS 9090 需登记 method-map / DAP TCP 6006 免登记),headless 与 bridge 域各维持单通道表述。否则下个"第 5 通道"工具(如 editor 域 profiling 直连)又落在表述空白区,需现场裁决。

#### D3 · defects 基线检测盲区(const Map 形态)

**证据**:`test/regression/defects.ts:1656` 的 detect 是 `countMatchesInDir('src', /^let _/gm, /\.ts$/)`,只匹配 `let _` 前缀——dap 3 处 + game-bridge 1 处 const Map 容器均不计数,护栏与自述("模块级可变状态基线")不符。

**建议**:detect 扩为 `/^(let|const) _/gm` 并按实测重定基线(const 容器形态 7 处 + let 66 处);或在该 defect 描述注明"const 容器形态豁免及理由"。二选一,不许沉默漂移。
