## Blocking Issues

### B-1:player 档"防看穿"承诺被四个未接线的 bridge 读数据出口击穿(置信 90)

六读通道接线完整,但 bridge 还有四个返回节点数据/存在性的出口在 player 档下原样泄露:

1. **get_tree**(mcp_bridge.gd:1169-1178):整树序列化无任何 profile 处理——直接违背"private 对象不进树"与"存在性不泄露"承诺。
2. **wait_for_node / wait_for_property**(:2333-2353):exists 布尔是存在性侧信道;wait_for_property 返回属性真实值不过投影。
3. **playtest.step / step_until 的 report 搭车**(_eval_structured_report :3176-3190 直读 n.get(rprop)):player 档下拿到真值。
4. **call_method 白名单内的纯读方法**(ALLOWED_METHODS :134-140 的 get/get_meta/get_children 等):call_method(path,"get",["position"]) 读任意属性真值、get_children 枚举 private 子树。审查指出:**ALLOWED_METHODS 本质是只读方法集(:1608 注释自称"设计为只读"),把它归为"动作通道"是分类错误——按入口名归类留下绕过路径。**

依据:尽调文档 §5.1.2"不可绕过性可保留(投影发生在游戏侧,agent 拿到的已是投影后数据)"——上述出口使该承诺失效。

### 审查同时暴露的更深缺陷(实现者自查补充,随 B-1 一并修)

请求级 profile 参数下 **agent 可自降级 debug 绕过投影**:env=debug,player 时 agent 全程不传 profile(默认 debug)即拿到全部真值——投影对 agent 是自愿的,"防看穿"不成立。gua 原语义是 host 持有 profile、agent 不能切换;enhanced 初版把 profile 做成请求级参数偏离了这一语义。

## 值得进 memory 的工程教训(审查者提炼 + 实现者补充)

1. **移植安全语义层时,接线点必须按"全部数据出口"枚举,不能按"功能点"枚举**——清单式设计天然漏"不在清单上的出口"(get_tree/wait/report/call_method 都不在"六读通道"清单上)。
2. **"动作通道 vs 读通道"要按数据流向判,不能按工具入口名判**——call_method 听起来是动作,其白名单却是只读集。
3. **请求级权限参数天然可被"不传参数"绕过**——host 侧防绕过必须是"强制上限"语义(静默提升),不是"可选授权"语义;授权清单(allowed)与强制档(forced)是两个正交概念。
4. **GD 的 JSON 数字统一反序列化为 float**:str(int 0)="0" ≠ str(float 0.0)="0.0"——跨 JSON 边界的 str 比较要显式统一形态(既有 wait_for_property 的 str 比较脆弱性)。
