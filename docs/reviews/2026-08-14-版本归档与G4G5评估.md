## 值得进 memory 的工程教训

1. **version-check 绿 ≠ CHANGELOG 完整**:`version-sync.mjs --check` 只校验元数据版本号一致,不校验 CHANGELOG 是否覆盖所有真实发布版本。归档多版本时,必须额外用 `git log -S "\"version\": \"X.Y.Z\"" -- package.json` 逐一核对每个 version bump commit 是否都有对应 CHANGELOG 段。本次 0.28.1 漏段就是只信 version-check 绿导致的盲区。

2. **归档多版本要先列版本清单再填段**:批量归档 [Unreleased] 为多个版本段时,正确顺序是"先用 pickaxe 列出所有 version bump commit → 确认版本序列无跳号 → 逐版本查区间 commit 分类 → 再填 CHANGELOG"。跳过"列版本清单"直接凭记忆归档,极易漏中间版本(本次 0.28.2/0.28.3 直接叠在 0.28.0 上,0.28.1 被吞)。

3. **changelog-sync advisory 是有效信号但要看穿误报**:脚本按"commit 日期 vs 最新版本段日期"判断,同天 commit 会误报。advisory 不阻断 CI,但告警列表里往往混着真漏登(本次 G2)。归档后应人工区分告警:已出现在已发布段的=误报,任何段都没有的=真漏登。
