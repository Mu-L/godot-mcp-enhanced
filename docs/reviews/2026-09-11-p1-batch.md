## 三、值得进 memory 的工程教训(审查者提炼)

1. **输出侧包装类防御的第一破坏面是消费方契约**:给输出加信封前必须先 grep 既有消费方(裸 JSON.parse、内部解析)——防护层改变输出格式,测试挂不是防护的错,是落地没扫消费方(B-1 根因)。
2. **错误消息是安全机制的可见面,新授权通道落地时所有提及旧通道的消息要同步枚举**(I-1 同函数双标)。
3. **同一数据源的多个出口,防护要么全包要么写明豁免理由**——不对称防护比不防护更误导(I-2)。
4. **install 幂等"不覆盖 differs"语义对 e2e fixture 是坑**:Windows EPERM 残留 + 幂等保留 = e2e 永远测旧代码(N-4 根因,通用模式:自管理测试资产要强制刷新,用户资产才适用保守保留)。
