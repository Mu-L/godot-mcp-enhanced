## 值得进 memory 的工程教训(审查者提炼)

1. **"瘦身后值 ≠ 触发判断输入"**:SLIM 阈值判断在变换前,读 registry/matrix 产物值判断"是否触发"必然口径错——判断机制是否生效要读**变换输入侧**。
2. **生成产物链的门禁不均衡**:build-matrix 有流程门禁,gen:tool-docs 没有——而 help 运行时读 docs/tools/,"改描述→matrix→tool-docs"应成一条链,否则 help 输出静默漂移 8 个版本(实测 v0.32.8 停摆)。
3. **报丧/清理类逻辑必须探活再判死**:"残留文件 + pid 非我" ≠ 死进程;多 server 并存是多会话工作流常态。
4. **保存/恢复进程级全局量要感知外部事件失效化**:saved 值代表保存瞬间的世界状态,恢复前若外部状态已变(引擎焦点事件),需事件信号把 saved 失效化。
