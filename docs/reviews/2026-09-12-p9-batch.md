## 审查发现与清偿

### N-1(置信 90,建议升格):include_raw 在 17/18 action 上无效——接口契约部分不实现

**发现**:schema 承诺"响应附带清洗后的原始 DAP request/response/messages",但成功路径只输出 {session_id, response},失败路径 `_dapRequestError` 收 `_args` 却未使用;仅 output action 实现。AI 在 dap 超时/失败时传 include_raw:true 想排障,静默拿不到(schema 撒谎——调试工具自身排障路径失效)。**SSOT 审计器没抓的原因**:include_raw 在代码里"被引用"(output 一处)即通过对账——审计器只校验"键是否被引用",不校验"schema 承诺的行为是否对所有 action 生效"。

**清偿**:`_sessionRequest` 成功路径补 include_raw 分支(request+messages);`_dapRequestError` 失败路径补 messages;回归用例 DAP-o(成功路径断言 request/messages 真实存在)。

### N-2(置信 85):set_settings 同批次 host+allow_remote_hosts 顺序回归

**发现**:TS 版逐键循环处理,host 分支校验时 allow_remote_hosts 还是旧值——同批次 {host: 远程, allow_remote_hosts: true} 报错(原实现 gd:555 专门把 allow_remote_hosts 提到循环外先应用)。

**清偿**:还原预处理顺序(循环前先应用 allow_remote_hosts);回归用例 DAP-p。

### N-3(置信 85):data pump 路径的超限错误丢失,降级为 dap_timeout

**发现**:push 模型(pump)里检出的 buffer/frame 超限只 close 会话,错误无处传递——上层报"超时"误导排障(真因是超限)。原实现 pull 模型可在读循环同步返回。

**清偿**:DapSession 加 pendingError 字段,pump 检出超限时记录,_readMessages 每轮优先报出;回归用例 DAP-q(mock 回巨型 Content-Length header 断言 error_code=DAP_LIMIT_EXCEEDED + 'frame exceeded')。

### N-4(置信 80):同 session_id 并发首连的 socket 覆盖泄漏

**发现**:_ensureSession 无 in-flight 去重,两个并发请求各自 _connect,后完成者覆盖前者 session(旧 socket 连同 pump listener 活到进程结束)。原 gd 实现同样存在(移植保留缺陷)。仓库先例 bridge-client.ts:483 有串行化模式。

**清偿**:_connectInflight Map(`sessionId@host:port` 键)复用同一 Promise;回归用例 DAP-r(3 并发 initialize 断言 session_count=1)。

### N-5(置信 90):token 预算 totalSum 回弹越 95KB warn 线无处理记录

**发现**:P4 批自定"回弹即警"语义,P8+P9 正当增量推至 ~103.9KB 越线,warn-only 不阻塞但无人处理。

**清偿**:warn 线校准 95→105KB(~1KB 余量,注释记录两批增量与审查出处);error 线 120KB 不变;同步更新 p4-batch SLIM-c 与 check-token-budget.test 两处阈值锁断言。

## 工程教训(登 memory)

1. **SSOT 审计器只对账"键被引用",不校验"schema 行为承诺实现"**——include_raw 引用一处即过,对 17/18 action 无效;参数级 schema description 的行为承诺是审计盲区,review 须人肉核对"声明行为↔每个消费点"。
2. **push+pull 混合模型的异步错误通道要重新设计**——gd pull 模型读循环可同步返回 limit error;TS pump 里检出的超限无处安放,静默降级为 timeout(N-3 的 pendingError 模式是通解)。
3. **移植时"看似冗余的预处理顺序"可能是有意设计**——gd 把 allow_remote_hosts 提到循环外是为支持同批次开远程+设远程 host;按常规顺序重写即回归(N-2)。
4. **批量计数替换绝不碰版本表历史行**——本批修复 P8 遗留的历史行误伤(248→252→270 连环),根因是两批都用"正则+语境过滤"批量替换;正确做法:新工具计数只改顶层当前描述行,版本表行只追加新行不改旧行。
