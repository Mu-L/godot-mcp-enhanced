## 值得进 memory 的工程教训

1. **skill 正文工具引用是审查盲区(第二次踩)**: Tier1-2 error_analyzer 笔误 + 本次 B-1 screenshot_compare/type=/before= 三处错误,都是 skill 正文工具引用无测试守护导致。审查 skill 时必须独立 grep 每个反引号标识符 + 核实参数签名,不能只看结构测试通过就放行。

2. **手写 skill 的"品味规则"需溯源官方文档**: B-2 的 set_trans/set_ease 顺序是凭空捏造,经 Godot 文档核实无此规则。写"品味审计"类 skill 时,每条规则必须能溯源到官方文档或行业共识,不能凭直觉编。

3. **手写 skill DRY 单源模式可行**: HANDWRITTEN_SKILLS map + buildAllSkills 合并 + build-skills.mjs 遍历 + DRY 一致性测试,这套模式工作良好,值得作为后续手写 skill 的标准范式。
