## 二、token 账本实测(上游行动 #1 的答案,✅主核)

| 口径 | 工具数 | 字节数 | ≈tokens | 对比 BuildersGate 105k |
|---|---|---|---|---|
| 全量(full profile) | 45 | 94,537 B | 23.6k | 22.5% |
| **默认 basic profile(实际连接默认值)** | 25 | 60,041 B | **15.4k** | **14.7%** |
| BuildersGate 基线 | 256 | 378,589 B | 105k | 100% |

测量方式:全量 = `npm run check:budget`(读 capability-matrix.json,统计每工具 descBytes + inputSchema JSON 字节);basic = 主会话 node 脚本按 basic 组清单(core/bridge/animation/audio/signal/visual/code/test/profiler)过滤 matrix 求和。

**四个判断**:

1. **action 扇入架构天然抗 schema 膨胀**:新 action 通常只往 enum 加一个短字符串 + description 加一行,远比新增顶层工具(独立 JSON schema)便宜。 BuildersGate 的"agent 在重读工具目录"拷问对 enhanced 杀伤力有限。
2. **BuildersGate 的 97.5% cache_read 恰说明大头走缓存价**——schema 成本的边际影响要看 cache miss 部分,把"105k/turn"直接当每 turn 全价是上游报告的口径简化。
3. **真正持续恶化的是描述膨胀速度**:G7 注释(`src/core/tool-registry.ts:206-209`)宣称 basic "79KB→~30KB 省 60%",2026-09-11 实测已是 60KB——单月翻倍。这指向 CI 守卫收紧(check:budget 已有 90KB warn 线)与描述重写,而非架构改造。
4. token 维度剩余实活 = **描述瘦身**(内容工作)+ **discover 按需发现评分**(确实空白);"分组默认最小激活"这半边已由 G7 完成。

- **机制**:全文 26 行。每次调用随机 nonce(`%08x" % randi()`),包裹不可信内容:`<untrusted-{nonce} kind="..." source="...">\n{body}\n</untrusted-{nonce}>`;nonce 模型不可预测 → 无法在注入内容里伪造闭标签提前"逃出"信封。**scrub 正则先洗掉 body 里已存在的一切 untrusted 标签变体**(开/闭、带任意 nonce、带属性、大小写、空白容错)替换为 `[scrubbed-envelope-tag]`——防嵌套伪造。只 wrap 读路径,不 wrap 写路径和二进制。**调用点 15 处**:script.read、scene tree、user-file、resource 属性、project settings、console、game_log、animation keys/nodes/transitions、audiobus。
- **威胁模型辨析**:`randi()` 非密码学随机——nonce 防的是"模型不可预测",不是"不可暴力"(每信封一次性出现,无重放面)。信封是否真防注入取决于客户端模型是否"尊重"标签语义——**软防御**,与 enhanced 现有"输出标记防伪造"(防 GDScript 伪造 MCP 输出)**正交**:这层防的是项目文件内容里藏的提示注入。
- **移植落点**:TS 侧 `src/core/untrusted-wrap.ts`(nonce 用 `crypto.randomUUID().slice(0,8)`),套在 GDScript 执行输出 / read_script / read_scene / get_debug_output / game_query 文本返回——项目内容进入模型上下文的主通道。**~40 行 + 每读工具 1 行**。

- **loud-fail**:带 e2e marker 的测试在引擎缺失时 `pytest.fail`(带解析路径与修复指引)**而不是 skip**——"e2e 层是强制本地门禁"。CI 分层:push 只跑非 e2e;engine/e2e 层 nightly;错误信息点名是哪层不够。
- **⚠️ `.pc` 日志 race(enhanced 直接适用)**:并发 e2e 各自启动 Godot 共享 `user://logs`,桌面端 RotatedFileLogger 在 rotate_file() race,**abort 伪装成 engine_crashed**(最阴险的 flaky)。修复 = 每个 fixture project.godot 关文件日志,且**必须同时写两个 key**:
  - `debug/file_logging/enable_file_logging=false`
  - `debug/file_logging/enable_file_logging.pc=false`
  base key 默认 false,但 **`.pc` feature-tag override 在桌面默认 true 且启动时获胜**(godot main/main.cpp)——**只关 base 是 no-op**。
- **移植落点**:enhanced 的 test/integration/ 与起 Godot 进程处统一注入双 key 关闭。**~20 行,半天,P0**。

## 八、方法论反思(对上游报告)

1. **单点 grep 证据会漏调用链语义**:"默认全量激活"的判断源于 `tool-registry.ts:243` 一行字面,但默认值在三跳之外(`index.ts:90` → `ToolDispatcher.ts:173` → `resolveProfile`)被覆盖。否定性论断("enhanced 没有 X")必须追到消费方,不能只看定义处。
2. **"schema 即成本"需校准后再当行动依据**:BG 的 97.5% cache_read 恰说明大头走缓存价;enhanced 默认 15.4k tokens 在赛道内是低位(≈BG 的 15%)。真正持续恶化的是**描述膨胀速度**(G7 注释 30KB → 实测 60KB,单月翻倍)——这指向 CI 守卫收紧与描述重写,而非架构改造。
3. **行号快照会漂移**:上游报告给 aigengame 的 gda_harness.gd 路径已漂移(examples → src/gda/harness);采用任何借鉴点前按快照护栏先 `grep -n` 重新定位。
4. **" proven 机制"要查审计器是否真的落仓**:regiellis 的 params 审计器不在仓库中,完备性只能靠注释自证——借鉴时审计器必须自己落仓。
