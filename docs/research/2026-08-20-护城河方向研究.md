# 护城河方向研究(2026-08-20)

> 研究背景:分发优先批(2026-08-19)收口后,回到护城河主线。上次系统核实是 2026-07-26(4 点 vs Godot AI,见 `D:\workspace\Obsidian\GodotMCP\开发日志\2026-07-26 护城河核实（4 点 vs Godot AI）.md`),此后赛道发生两件事:① Godot AI 近月 9 个版本高速迭代;② yanhuifair/Godot-MCP 以 386 工具异军突起并把「Deterministic」术语绑在其伪确定性实现上。本轮目标:**复核护城河点现状 + 定位下一阶段加固方向**。
>
> 数据来源:两个并行调研子代理(Godot AI / yanhuifair,commit+源码级,窗口 2026-07-20→08-20)+ 我方本地实测。我方数字核查命令随文标注;竞品证据带 commit SHA/文件路径,完整报告见本文附录指针。

## 一、结论摘要

1. **9 个护城河点中 8 个保持差异化,1 个(安全体系)被 yanhuifair 部分追平**(网络面/路径面已同档;执行沙箱/审计/PII/确认门四子项仍我方独有)。
2. **最高风险不是能力被追平,是术语被抢注**:yanhuifair README 把「Deterministic frame stepping」绑在 freeze/step/截图三件套上(无 RNG 锁定、无 fixed_delta;且其 v1.8.0 的该功能因 `runtime_bridge.gd` 硬解析错误 dead on arrival,v1.10.0 才修好),并对外声称「No other public Godot MCP does this / ❌ None」。Godot AI 的 `input_sequence`(#842,`2582158`)也把「reproduces identically across runs」立为设计目标——确定性叙事正在被两家分头蚕食。
3. **我方一个真实能力空白**:帧定时输入时间线(竞品称 input_sequence)。bridge 输入是即时注入,qa 编排靠 `input`+`wait_frames` 组合近似,帧对齐不严格。补上后确定性测试域成完全体(seed 锁随机+fixed_delta 锁步长+freeze 锁暂停+**时间线锁输入**+step_until 条件步进+snapshot/restore 状态恢复)。
4. **两个反转发现(评估时勿自贬)**:① write_script/edit_script 的 `auto_validate`(语法失败自动回滚,`src/tools/script.ts:613,664,797`)比 Godot AI script_patch 的诊断透传更强——它只展示 parse 诊断,我方失败即 revert;② editor 层 undo `create_action` 实测 45 处分布 8 个命令文件(核查:`grep -c "create_action" addons/godot_mcp_server/commands/*.gd`),远超 yanhuifair 的 12 命令——它却把「Every scene edit is one Ctrl+Z away」讲成了 README 主打叙事。

## 三、竞品近月动态要点(证据见子代理报告)

- 工程执行力基线高(pytest 1682+GDScript 套件 2100+ 用例,做过全仓安全审计闭环),它不做验证/审计是优先级选择非能力缺失。

## 四、方向建议(三层)

### 第一层:叙事正名(低成本,即刻可做,不需发版)
- **N1 「确定性分级」公开对照**:把确定性测试能力分级讲透——L1 帧步进(仅能暂停+推进)/L2 输入时序锁定/L3 RNG 锁定+fixed_delta+条件步进+快照恢复(=真确定性,复现需要随机状态+物理步长+输入三者全锁)。在 README 现有 p5 打假脚注基础上升级为独立小节,并以 yanhuifair 公开 README 为对照样本(其 `runtime_step` schema 仅 `frames` 一个可选参数,证据:`src/tools/runtime.ts` runtimeStepSchema)。**这是对「术语抢注」的防御性正名,不是攻击性营销。**
- **N2 Undo 叙事补位**:我方 editor 层 create_action 45 处(8 命令文件)远超竞品,但 README 一句没讲。加一行「editor 层操作全走 Godot 原生 undo 栈(实测 45 处 action 注册),AI 改错一步 Ctrl+Z 即回」。
- **N3 确定性 playtest 的 demo 化**(Godot AI 的 Cyberpunk HUD demo 模式已验证有效性):一段「freeze→step_until(血量<30%)→断言→snapshot/restore 复跑对照」的 gif/短视频,把 playtest 讲成 headline feature(yanhuifair 用 11 个工具讲出了我们 6 原语没讲出的故事)。

### 第二层:能力加固(中成本,下批候选)
- **H1 帧定时输入时间线原语(推荐首选)**:bridge 新增 `send_input_sequence`(参数 `[{at_frame, action, pressed, strength}]`,在 freeze 窗口内按帧注入,配合既有 seed/fixed_delta 形成确定性测试完全体)。借鉴 Godot AI #842,但我方叠加 freeze/step 语义后能力代差反而拉大(它无暂停/无 seed,时间线只能对运行中游戏播)。需 GD 侧实现+qa 步骤类型接线,预计 2-3 天。
- **H2 Vision Routing 产品化差距评估(可 defer)**:Godot AI 带 UI/加密存储/3 provider/带图测试连接;我方 env key+参数开关。headless MCP 形态下 UI 非刚需,建议 defer,观察用户诉求再动。
- **H3 理解层深化(中优先级)**:GodotIQ $19 买断验证理解层付费需求;我方 analysis(signal_map/impact_check)已是免费开源底座,可深化 project_summary/token 分级/跨版本 API 迁移分析(结合 lint 的 extension_api.json 底座)。宽度补齐,非护城河本质。

### 第三层:战略定位(研究方向)
- **S1 「AI 游戏开发的 CI/CD」定位卡位**:竞品全部押 authoring(生成侧),无一押 verification(验证侧)闭环。我方 qa nightly+回归 diff+审计回放+确定性 playtest 的组合,本质是「AI 写代码的持续验证管线」——与 24k★ Claude-Code-Game-Studios(49 agents 工作室,生成侧)结构性互补:工作室生成,enhanced 验证。建议把这个定位讲进 README 顶部叙事(「not just another Godot MCP — the verification layer for AI game development」方向),并考虑一个模板项目/教程演示「AI 开发循环:生成→自动验证→回归检测」。
- **S2 真实项目 showcase**:CardGameGodot2 等自用项目持续作为案例素材(竞品 demo 全是人造场景,真实项目叙事更可信)。
