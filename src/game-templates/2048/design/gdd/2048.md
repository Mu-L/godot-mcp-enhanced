# 2048(数字合并)

> 模板 slug: `2048` · 调参: `tuning-src/2048.csv` → `tuning/2048.tres` · qa: `qa/2048.qa.md`

## Overview

4×4 网格上的数字滑块合并游戏:方向键移动全部方块,相同数字碰撞合并翻倍,每步在空位随机生成新方块(90% 概率 2、10% 概率 4)。合并出 2048 获胜;网格满且无可合并步判负。得分 = 每次合并产生的新值累加。

## Player Fantasy

「数字在指尖翻倍生长」——每一把都有清晰的因果:按一下方向,局面收敛一步,分数跳一格;从 2 摸到 2048 的过程是连续的小成就链。失败时能明确归因(哪一步把大数锁死了),激发立即重开。

## Detailed Rules

1. 开局:空网格随机放置 `start_tiles`(默认 2)个新方块(2 或 4,按概率);
2. 方向输入(Left/Right/Up/Down):该方向上所有方块整体滑移到底;每行/列内相同数字相邻碰撞时合并一次(同一次移动中每个方块最多参与一次合并),合并方向朝移动方向;
3. 滑移后若局面有变化,随机空位生成 1 个新方块;局面无变化则不生成、不计步;
4. 每次合并的得分 += 合并结果值;
5. 胜利:任意方块达到 `win_value`(默认 2048),置 `won=true`,游戏继续可玩;
6. 失败:网格满且四个方向均无合法合并,置 `game_over=true`。

## Formulas

- `score = Σ merge_value`(每次合并加合并结果,如 2+2=4 得 4 分);
- 新方块取 4 的概率 = `1 - four_probability`(默认 two_probability=0.9 表示 90% 出 2);
- 有效步判定:`board_changed == true` 才生成新块、`moves += 1`;
- 理论最大值 = `2^(grid_size^2 + 1)`(4×4 理论上限 131072)。

## Edge Cases

- 一次移动中三个相同数字相邻(如 2,2,2):移动方向最前端的两个先合并(得 4),第三个 2 不再合并;
- 四个相同(2,2,2,2):合并为 4,4 两组;
- 输入方向上无任何方块可动:不生成新块、不计步(避免空转惩罚);
- 胜利后继续合并更大数字(不强制结束);
- `grid_size` 奇数合法可玩;<2 或 >16 时按边界钳制(防御)。

## Dependencies

- Godot 4.5–4.7(仅内置节点:Node2D/ColorRect/Label,零外部资产、零 autoload、零插件);
- 调参资源 `tuning/2048.tres`(`GameConfig2048` Custom Resource,`_ready` 加载,缺失时用默认值);
- 键盘方向键(Physical keys `Left/Right/Up/Down`)。

## Tuning Knobs

| 旋钮 | .tres 字段 | 默认 | 效果 |
|---|---|---|---|
| 网格边长 | `grid_size` | 4 | 3=快节奏,5=宽松(可动步更多) |
| 胜利值 | `win_value` | 2048 | 256=短局,8192=马拉松 |
| 出 2 概率 | `two_probability` | 0.9 | 调低=更多 4,难度上升 |
| 开局块数 | `start_tiles` | 2 | 调大=开局更拥挤 |

改表工作流:编辑 `tuning-src/2048.csv` → 用 `csv_to_resources` 重导 `2048.tres` → 重启游戏生效。

## Acceptance Criteria

1. 开局恰好 `start_tiles` 个方块,均为 2 或 4;
2. 同 seed(如 42)+ 同输入序列 ⇒ 每步后棋盘布局、`score`/`moves` 完全一致(确定性,qa 两跑 diff 零回归);
3. 方向时间线 4 次输入后 `moves == 4` 且 `score >= 0` 且未结束;
4. 2,2,2 合并结果为 4,2(单次合并语义);
5. 网格满且无合并可能时 `game_over == true`。
